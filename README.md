# Engenharia e arquitetura

Ao desenvolver um produto, procuro partir da regra de negócio antes da implementação.

```text
Problema real
      ↓
Regras de negócio
      ↓
Domínio
      ↓
Arquitetura
      ↓
Modelo de dados
      ↓
Segurança e permissões
      ↓
APIs e serviços
      ↓
Experiência do usuário
      ↓
Testes
      ↓
Deploy
      ↓
Observabilidade e evolução
```

Alguns princípios que aplico:

- simplicidade antes de complexidade;
- tipagem forte e contratos claros;
- separação de responsabilidades;
- modelagem orientada ao domínio;
- segurança desde a camada de dados;
- autorização validada no backend;
- Row Level Security para isolamento de dados;
- migrations incrementais e não destrutivas;
- componentes reutilizáveis;
- testes para regras críticas;
- mobile-first quando o contexto exige;
- IA integrada ao produto de forma estruturada.
